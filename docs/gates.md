# 핸드오프 게이트

에이전트 사이에 산출물을 넘길 때마다 게이트를 통과시킨다. 게이트는 **다음 담당이 작업을 시작해도 되는가**만 판정한다. 수업의 교육적 효과나 최종 품질을 보장하지 않는다. 항목 정의의 원본은 [`gates/gates.json`](../gates/gates.json), 기록 검사는 [`tools/gate_check.py`](../tools/gate_check.py)이다.

## 흐름

```
총괄 ─명세 v0─▶ [G1] ─▶ 아이디어 ─선택안─▶ [G2] ─▶ 지도안
지도안 ─확정 지도안·동결 명세─▶ [G3] ─▶ 활동지 / 슬라이드 / 형성평가  (담당별로 각각 판정)
각 제작 담당 ─산출물─▶ [G4] ─▶ 통합 검토
통합 검토 ─판정표─▶ [G5] ─▶ 총괄 → 사용자 전달
```

## 핵심 원칙

1. **받는 쪽이 판정한다.** 게이트 기록의 `judge`는 `receiver`와 같아야 한다. 보낸 쪽은 자체 점검을 첨부할 수 있지만, 그 점수로 통과시키지 않는다. 보낸 쪽이 스스로 판정한 기록은 무효다.
2. **판정은 규칙으로 계산한다.** 항목 상태는 `pass` / `warning` / `block` / `not_assessed`이다. 결과는 아래 규칙으로만 정해지며, 판정자가 임의로 바꾸거나 같은 판정을 반복해 통과로 만들지 않는다.
   - `must` 항목에 `block` 또는 `not_assessed`가 하나라도 있으면 → `revision_required`(반려)
   - `must` 항목에 `warning`이 있으면: 조건부를 허용하는 게이트(G1·G2·G4)는 `conditional_ready`, 허용하지 않는 게이트(G3·G5)는 `revision_required`
   - `should` 항목만 미흡하면: 조건부 허용 게이트는 `conditional_ready`, 그 외는 `ready`이되 `conditions`에 남긴다
   - 모두 `pass`면 `ready`
3. **입력을 고정한다.** 공통 명세와 입력 파일의 경로와 SHA-256을 기록한다. 파일이 바뀌면 기존 판정을 쓰지 않고 다시 검사한다. 특히 G3에서 동결한 명세 해시는 G4까지 그대로 이어져야 한다.
4. **사용자 확인은 명시적이어야 한다.** G3는 사용자의 지도안 확인 발화를 `user_confirmation.quote`에 그대로 남겨야 통과한다. 침묵, 답변 부재, 대기 시간 경과, 아이디어 선택만으로는 확인으로 보지 않는다.
5. **반려 한도를 둔다.** 같은 명세 버전에서 같은 게이트의 반려는 최대 2회다. 세 번째 반려가 필요하면 자동 반복을 멈추고, 총괄이 원인·부분 결과·필요한 사용자 결정을 보고한다.
6. **판정이 충돌하면 차단을 유지한다.** 보낸 쪽과 받는 쪽의 판단이 다르면 문제 위치와 근거를 비교한다. 해결되지 않은 `block`은 유지하며, 없는 사용자 결정을 만들어 내지 않는다.

항목표는 `gates/gates.json`에서 생성한다(`python tools/gate_check.py docs --write`). 직접 고치지 않는다.

## 기록과 검사

- **기록 위치:** 게이트 기록은 `tmp/<수업명>/gates/<게이트>_<보낸담당>_to_<받는담당>_<YYYYMMDD-HHMMSS>.json`에 UTF-8로 저장한다. 기존 기록은 덮어쓰지 않고, 반려 뒤 재검사는 `new --previous <직전 기록>`으로 만든다. `previous_record`와 `rejection_count`는 이 연쇄에서 계산되며 스크립트가 일치를 검사한다.
- **필수 키:** `gate`, `lesson`, `checked_at`(+09:00), `sender`, `receiver`, `judge`, `spec{version,path,sha256}`, `inputs[]`, `checks[{id,status,reason,location}]`, `decision`, `conditions[]`, `revision_requests[]`, `rejection_count`, `previous_record`이 있어야 한다. G3에는 `user_confirmation{confirmed,quote,at}`이 추가된다. G4·G5는 검사한 산출물을 `inputs[]`에 경로와 SHA-256으로 남겨야 한다.
- **작성 규칙:** `pass`가 아닌 항목에는 `reason`과 가능한 경우 `location`(파일·쪽·활동 번호)을 적는다. 학생·학교 식별정보는 reason·location에 옮기지 않는다.

```bash
# 빈 기록 만들기(명세 해시 자동 기록)
python tools/gate_check.py new G3 --lesson 정보화사회와도덕 --sender lesson-plan \
  --receiver worksheets --spec tmp/정보화사회와도덕/spec.md --spec-version v3
# 판정 작성 후 검사
python tools/gate_check.py check tmp/정보화사회와도덕/gates/G3_lesson-plan_to_worksheets_20261014-101500.json
# 반려 뒤 재검사 기록(반려 횟수 자동 계산)
python tools/gate_check.py new G3 --lesson 정보화사회와도덕 --sender lesson-plan --receiver worksheets \
  --spec tmp/정보화사회와도덕/spec.md --spec-version v3 --previous <직전 기록>.json
# 인계 전 기록 연쇄 확인: 필요한 기록이 있고 통과했으며 G3 동결 해시와 G4·G5 해시가 같은가
python tools/gate_check.py verify --lesson 정보화사회와도덕 --through G4
```

| 종료 코드 | 의미 | 총괄의 조치 |
|---|---|---|
| 0 | ready | 다음 담당에 인계 |
| 10 | conditional_ready | `conditions`를 인계 메시지에 포함해 인계 |
| 20 | revision_required | 보낸 담당에게 `revision_requests`로 반려하고 `rejection_count`를 1 올림 |
| 2 | 기록 형식 오류 | 판정을 쓰지 않고 기록 보완 |
| 3 | 입력 변경 | 현재 파일로 새 기록을 만들어 재검사 |
| 4 | 반려 한도 초과 | 자동 반복 중지, 사용자에게 원인·부분 결과·필요한 결정 보고 |
| (verify) 5 | 기록 연쇄 문제 | 누락·미통과·명세 해시 불일치를 해소하기 전에는 다음 단계로 넘기지 않음 |

Python을 실행할 수 없는 환경에서는 같은 규칙을 수동으로 적용하고, 보고할 때 "스크립트 검사 미실시"라고 밝힌다. 기록 없이 "게이트 통과"라고 보고하지 않는다.

## 스크립트가 확인하는 것과 못 하는 것

| 확인함 | 확인할 수 없음(사람·총괄이 원자료로 대조) |
|---|---|
| 기록 형식, 보낸 쪽·받는 쪽 지정, 판정자≠보낸 쪽 | 판정자가 실제로 다른 에이전트인지 |
| 결과의 규칙 계산, 미흡 항목의 `conditions` 기재 | 각 `pass`가 실제 사실인지 |
| 명세·산출물 파일 해시, G3→G4→G5 명세 해시 일치 | 해시를 계산한 파일이 올바른 파일인지 |
| 반려 횟수의 기록 연쇄, 한도 초과 | 기록 폴더 밖에서 기록을 새로 쓰는 경우 |
| 사용자 확인 인용이 비어 있지 않고 시각이 있음 | 인용이 실제 대화에 있는지 → 총괄이 대화 원문과 대조 |

`tmp/`는 저장소에 올리지 않으므로 실행 환경이 사라지면 기록도 사라진다. 총괄은 최종 전달 목록에 게이트별 결과와 `verify` 출력을 옮겨 적는다.
